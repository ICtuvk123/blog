Architectures and Hyperparameters

This lecture is about the architectural choices that have become standard in modern language models. Many of these choices look small in isolation: where to put LayerNorm, whether to keep bias terms, how to parameterize the feedforward block, how to represent position, and how to reduce the cost of attention. But together they define the practical transformer recipe used by most recent LMs.

Pre-norm as the modern default

The first architectural question is where normalization should sit inside a Transformer block. The original Transformer used post-LayerNorm: apply attention or the feedforward network, add the residual connection, then normalize. Most modern language models use pre-norm: normalize the input before the sublayer, then add the residual output back to the main stream.

The reason this matters is optimization. In a deep residual network, the residual stream is the main path through which information and gradients move. Pre-norm keeps that path more direct, because LayerNorm does not sit after every residual addition. Post-norm was used in older models such as BERT, but pre-norm has become the default for large LMs.

The empirical story also supports this shift. The pre-vs-post-norm comparison shows that pre-norm variants train more stably and can often avoid some of the warm-up sensitivity seen in post-norm models.

One explanation is gradient behavior. Post-norm can suffer from gradient spikes or unstable gradient scaling, especially early in training. Pre-norm makes very deep transformers easier to optimize and supports larger learning rates in large networks.

The historical motivation was sometimes framed as removing warm-up. Today the more important takeaway is broader: pre-norm is a stability choice for deep models.

LayerNorm and RMSNorm

The original Transformer used LayerNorm. LayerNorm normalizes both the mean and variance across the model dimension:

$$ \mathrm{LayerNorm}(x) = \frac{x - \mathbb{E}[x]}{\sqrt{\mathrm{Var}(x) + \epsilon}} \cdot \gamma + \beta $$

Many modern models instead use RMSNorm. RMSNorm removes the mean subtraction and usually omits the bias term:

$$ \mathrm{RMSNorm}(x) = \frac{x}{\sqrt{\frac{1}{d}\|x\|_2^2 + \epsilon}} \cdot \gamma $$

The simple explanation is that RMSNorm is faster and tends to work just as well. It avoids computing the mean and stores fewer parameters because there is no bias term. Models such as the LLaMA family, PaLM, Chinchilla, and T5 use RMSNorm-style normalization, while earlier GPT-style models and OPT used LayerNorm.

At first glance, the runtime argument may seem too small to matter, because matrix multiplications dominate FLOPs.

But FLOPs are not runtime. Normalization can be a small fraction of FLOPs while still taking a meaningful fraction of wall-clock time, because it involves data movement and memory access patterns that are less efficient than large matrix multiplications.

This is one of the recurring systems lessons in architecture design: an operation can be cheap in arithmetic and still matter in runtime.

Dropping bias terms

Many modern transformers also drop bias terms. In the original feedforward network, the block looked like:

$$ \mathrm{FFN}(x) = \max(0, xW_1 + b_1)W_2 + b_2 $$

Modern implementations often remove these biases:

$$ \mathrm{FFN}(x) = \phi(xW_1)W_2 $$

The reasons are similar to RMSNorm: less memory movement, fewer parameters, and often more stable optimization. The savings from one bias vector are small, but across many layers and very large models, these simplifications become part of a cleaner and more efficient design.

Gated feedforward layers

The feedforward block has also changed. Instead of a plain two-layer MLP with ReLU or GELU, many modern models use gated variants such as GeGLU and SwiGLU.

The key idea is to compute two projections from the input. One projection produces values, and the other produces a gate. The output is formed by multiplying them before the final projection:

$$ \mathrm{GeGLU}(x) = (\mathrm{GELU}(xW) \odot xV)W_2 $$

SwiGLU replaces GELU with Swish:

$$ \mathrm{SwiGLU}(x) = (\mathrm{Swish}(xW) \odot xV)W_2 $$

Gated feedforward layers are used in many recent models, including LLaMA-style models, PaLM, Mistral, and others. Because the gated block has extra projections, the hidden dimension is usually reduced compared with the classic factor-of-4 feedforward size. A common rule is to use about $2/3$ of the original feedforward dimension.

Parallel layers

Most Transformer blocks serialize attention and the MLP: run attention, add it to the residual stream, then run the MLP. Some models, including GPT-J, PaLM, and GPT-NeoX, use a parallel formulation.

In the standard serialized block, attention and MLP are computed one after another. In the parallel version, both receive the same normalized input:

$$ y = x + \mathrm{Attention}(\mathrm{LayerNorm}(x)) + \mathrm{MLP}(\mathrm{LayerNorm}(x)) $$

If implemented carefully, the shared normalization and input matrix multiplications can be fused, which can make training faster. GPT-J reported roughly a 15% training speedup at large scale. There may be small quality tradeoffs at smaller scales, but large models appear to tolerate the parallel structure better.

The note "Lost half of depth!" is a useful warning: when attention and MLP are parallelized, the effective sequential depth changes. The model may run faster, but the meaning of depth is not identical to the serialized Transformer.

RoPE: rotary position embeddings

A language model needs position information, but we would like attention to depend on relative position when possible. If token $i$ attends to token $j$, the relevant distance is often $i - j$, not the absolute locations separately.

RoPE, rotary position embeddings, is designed around this idea.

Absolute positional embeddings inject position directly into token representations, which makes the representation depend on the absolute index. Sinusoidal embeddings have useful structure, but when combined with token embeddings additively, they introduce cross terms that are not purely relative. Relative position embeddings solve part of the problem, but they are not naturally expressed as an inner product between rotated query and key vectors.

RoPE uses a different trick: rotate the query and key vectors according to their positions.

Inner products are invariant to applying the same rotation to both vectors. So if position is encoded as a rotation, then the inner product between a query at position $i$ and a key at position $j$ can depend on the relative rotation between them, which corresponds to $i-j$.

The actual implementation pairs coordinates and applies rotations with different frequencies.

The RoPE matrix is block diagonal, with each pair of dimensions rotated by sine and cosine terms:

$$ \begin{pmatrix} \cos(m\theta_1) & -\sin(m\theta_1) \\ \sin(m\theta_1) & \cos(m\theta_1) \end{pmatrix} $$

applied across multiple coordinate pairs.

The important difference from additive sinusoidal embeddings is that RoPE changes the geometry of the query and key vectors through rotation. It does not simply add a position vector to the token representation.

Weight decay in LLMs

Weight decay is often introduced as a regularizer to control overfitting. In large language models, the story is more subtle.

The slide points to observations from Andriushchenko et al. 2023: weight decay interacts strongly with learning rate schedules, especially cosine decay. Its effect is less about classical overfitting control and more about optimization dynamics.

This is part of why architecture and hyperparameter lectures can feel strange. Some choices look like regularization, but their practical effect is often mediated through training stability, learning-rate interaction, and large-scale optimization behavior.

Hyperparameter summary

Several broad rules of thumb appear repeatedly in modern model design.

The feedforward dimension often follows a factor-of-4 rule for standard FFNs, and about $8/3$ for GLU-style feedforward blocks. The head dimension and number of heads usually satisfy:

$$ d_{\text{model}} = n_{\text{heads}} \cdot d_{\text{head}} $$

Aspect ratio choices have a wide range of good values, often shaped by systems concerns. Regularization is still present, but its effect is frequently tied to optimization dynamics rather than only generalization in the small-data sense.

Softmax stability: z-loss

The output softmax can become numerically unstable if the normalizer grows too large. PaLM used an auxiliary z-loss to encourage the log normalizer to stay close to zero.

If $Z(x)$ is the softmax normalizer, the auxiliary term has the form:

$$ L_z = \alpha \log^2 Z(x) $$

This does not replace the language modeling loss. It adds a small stability pressure on the logits. Similar ideas appear in Baichuan 2, DCLM, OLMo 2, OLMo 3, and related models.

Attention softmax stability: QK norm

The attention softmax has its own stability issues. Attention logits come from query-key dot products, and these logits can become poorly scaled.

QK norm addresses this by applying LayerNorm or RMSNorm to queries and keys before the softmax. This stabilizes the magnitude of attention scores. The trick appears in models such as DCLM, OLMo 2, Gemma 2, Qwen3, OLMo 3, and later Gemma models, and it also has roots in vision and multimodal models.

This is a place where training can develop degeneracies, so controlling the scale of query-key interactions is often useful.

Logit soft-capping

Another stability technique is logit soft-capping. The idea is to cap logits smoothly using a tanh transformation:

$$ \mathrm{logits} \leftarrow c \cdot \tanh\left(\frac{\mathrm{logits}}{c}\right) $$

This keeps logits between $-c$ and $c$. The slide mentions using different caps for self-attention layers and the final layer. This can prevent logits from blowing up, though the technique may introduce performance tradeoffs and is more associated with some Google model families than with all modern LMs.

GQA and MQA: reducing attention head cost

During training on full sequences, attention has high arithmetic intensity. There are large matrix multiplications for $QK^\top$, softmax, and the value mixing step, so GPUs can be kept busy.

The incremental generation case is different. When generating text one token at a time, the model cannot parallelize across future tokens. It has to reuse the KV cache and update attention step by step.

Now the cost shifts. The model repeatedly reads keys and values from the KV cache. Arithmetic intensity becomes worse because memory movement grows relative to computation.

Multi-query attention (MQA) reduces this cost by sharing keys and values across heads. Instead of each head having its own keys and values, the model has multiple query heads but fewer key/value heads.

This significantly reduces KV cache memory traffic. The tradeoff is expressiveness: sharing keys and values makes attention cheaper, but it constrains what different heads can represent.

Grouped-query attention (GQA) is a middle ground.

Instead of using one shared KV set for all query heads, GQA groups query heads and gives each group its own keys and values. This creates a knob between standard multi-head attention and MQA. More KV groups preserve more expressiveness; fewer KV groups improve inference efficiency.

Sparse and sliding-window attention

Full attention over the entire context is quadratic in sequence length. For long contexts, this becomes expensive.

Sparse or sliding-window attention reduces this cost by limiting which tokens each position can attend to. This trades expressiveness for runtime. Some models alternate between full attention and structured sparse patterns, while others use local windows or special global tokens.

The common theme is the same as earlier architecture choices: large language model design is not only about mathematical expressiveness. It is also about stability, memory movement, and how well the computation maps to hardware.

Closing remarks

This lecture connects many small architecture decisions into a single practical picture. Pre-norm improves optimization stability. RMSNorm and bias removal reduce unnecessary memory movement. Gated feedforward blocks improve capacity allocation. RoPE gives attention a relative-position structure. Stability tricks such as z-loss, QK norm, and logit soft-capping control the scale of softmax computations. GQA, MQA, and sparse attention reduce inference-time memory and attention cost.

None of these choices alone defines a modern language model. Together, they form the current engineering recipe for making deep transformers train stably and run efficiently.
